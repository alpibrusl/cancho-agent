# cancho-agent design

## 1. What it is for
An agent in a backend (cancho-ota's assistant first) needs four things that are not about any one product: talk to a model whatever its API, let it use tools, keep the loop bounded, and speak the standard agent protocols. This library is those, and nothing about trips.

## 2. The neutral conversation (`msg`)
A conversation is JSON text: `[{"role":"system","text":..},{"role":"user","text":..},{"role":"assistant","text":..,"calls":[{"id","name","args"}]},{"role":"tool","id","name","text"}]`. The arguments of a call and the schema of a tool are **JSON kept as a string**: the providers disagree on how to write them (OpenAI wants a string, Anthropic an object), and the library's JSON tape has no byte range for an object, so a string is the one form every adapter can read and write exactly. Tool results are data: they are never put in a system or user message.

## 3. Adapters and the loop
`openai.request/reply` and `anthropic.request/reply` are pure: a body out, a body in. `reply` gives (ok, an assistant message, why it stopped, tokens in, tokens out), so a refusal, an error body or garbage is `ok = false`, never a crash. The loop is the caller's (it is I/O), `agent.decide` says what to do after each answer: a spent token budget stops everything, a cut-off answer is not an answer, tools are run only if a step is left to use their results.

## 4. Transport and policy
`transport` is native HTTPS (cancho's `http-client` and `tls`), taken from cancho-code. It takes the host and the address as arguments: resolving, and which hosts are allowed, is the caller's policy (an agent that must make no external call refuses any address that is not private). Keys are read by the caller and live only in a header line.

## 5. Checked
Pure tests by hand-written expected JSON for every adapter case (a conversation with a tool turn, several tool results in one turn, a nested argument that must be written out again, a cut answer, an error body, garbage) and for every decision. **Live**, opt-in: Claude Haiku 5.5 and Mistral Small each answered a question and ran a tool (an `add` tool the model called in step 1 and used in its step 2 answer).

## 6. Not built yet
* **Protocols.** MCP client (use any MCP server's tools), A2A (an agent card, tasks over JSON-RPC and server-sent events), AG-UI (the event stream a front end reads from an agent) and A2UI (declarative UI messages an agent sends). They are JSON over HTTP, so they fit this library as modules beside the adapters; none is written, and none will be written from memory: each needs its current specification read first.
* A server-sent events reader (streaming answers), a streaming reply parser, retries with backoff in the loop, a host policy module, and a tool table helper (name to function).

## 6. An MCP client over stdio
`mcp` (pure) builds the JSON-RPC lines and reads the answers; `shell` runs a command with input and captures its output (taken from `ota_assistant`'s model command); `mcp_stdio` runs the operator's server command **one process per request** and picks out the answer; `bin/mcp_probe` is a terminal front for it.
* **Written from the specification as a subagent read it on 2026-11-06, not from memory, and not yet confirmed against a modern server.** Two eras are spoken. *Modern (revision 2026-07-28):* no handshake; every request carries `_meta` with the protocol version, the client's info and its capabilities; a server answers `server/discover`. *Legacy (2025-11-25):* `initialize`, the server's answer, then the notification `notifications/initialized`, then requests. `detect` sends `server/discover`: a result means modern, any other answer means legacy, a command that cannot be run means neither. stdio is one JSON message per line; the server writes nothing else to its standard output and its standard error is not kept.
* **Why a process per request.** The modern protocol keeps nothing between requests, so this is its natural shape, and it keeps a server that crashes or hangs from taking the agent with it (bounded by 256 KB of output and a timeout the caller sets). The cost is a process start per call; a server that insists on a session is not served by this.
* **What it reads.** `tools/list` (pages followed by `nextCursor`, at most five) into the neutral tools of `msg` (name, description, the schema as a string; a tool with no name is left out, a schema that is not an object becomes `{"type":"object"}`). `tools/call` into text for the model: the `text` items joined by newlines, a placeholder for an image, audio, resource link or embedded resource, the structured content as JSON when there is no text. `isError` is the tool's own failure and is given to the model to correct; a JSON-RPC error is a refusal, said as a sentence ("The tool server refused the call: -32602: Unknown tool: x"), and a server that said nothing or ended badly is a sentence too. Notifications and answers to other ids are skipped. **A tool's text is data, never instructions** (cancho-code's own server says so in its instructions): nothing here puts it anywhere but the model's tool-result message.
* **Not built.** Streamable HTTP (a POST with `Accept` for JSON and for an event stream, `MCP-Protocol-Version`, `Mcp-Method` and `Mcp-Name` headers; no session id in the modern era). Server-initiated requests and the multi round trip `input_required` result (a client that declares no capabilities is not sent any, per the specification as read). Cancellation, progress, resources and prompts. The tools of an MCP server are not yet offered to the assistant of the group trip planner.
* **Checked.** `tests/mcp_test.cho` (5 tests: the requests of both eras byte for byte, the answer found among notifications and noise, an error's text, a page of tools into neutral tools, every kind of tool result); 22 mutants, all killed but two equivalent ones (a request id that is a string and not a number is already refused by the number comparison; `{}` is sent for an empty argument whichever way its length is tested). `tests/mcp_check.sh` runs the client against `tests/fixtures/mcp_server.py` (a fake written from the same reading, in each era, plus a server that says nothing and one that crashes): 27 checks, including a second page by its cursor, a tool that fails, an unknown tool, an argument with a quote and an accent, a call in the wrong era. **Against a real server** (cancho-code's, `src/mcp.cho`, a legacy-era server written independently, run with `--root /tmp/x --provider p --model m --build-bin /bin/true --board-bin /bin/true --prices f --checker /bin/true --agent-command true`): the era was found (legacy), the real tools were listed and a call to `cancho_status` returned that server's own error as a failed result. This check is by hand and not in the scripts. No server of the modern era was available to try.
